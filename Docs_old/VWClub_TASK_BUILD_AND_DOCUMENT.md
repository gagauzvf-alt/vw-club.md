## 0. Цель

Собрать и подготовить к запуску новый сайт **VW Club Moldova** на домене `vw-club.md`:

- самостоятельный технический клубный портал Volkswagen в Молдове;
- двуязычный сайт RU/RO;
- техническая база знаний по моделям, моторам, коробкам и эксплуатации Volkswagen;
- вход в Facebook-сообщество клуба;
- аккуратная интеграция BRAVO MOTORS как официального сервис-партнёра;
- статический production-сайт на Astro;
- локальное редактирование контента через Keystatic;
- автоматический деплой собранного `dist/` по FTP через GitHub Actions;
- полная живая документация, достаточная для продолжения работы в новом чате без чтения всего репозитория.

Сайт не является сайтом автосервиса и не должен выглядеть как рекламная воронка. Главная ценность — клуб, практическая техническая информация и помощь владельцам Volkswagen.

## 12. Деплой

Подготовь workflow по проверенному шаблону:

```yaml
on:
  push:
    branches: [main]
```

- сборка Astro создаёт `./dist/`;
- FTP публикует содержимое `dist/`;
- `server-dir: ./` допустим только если FTP-пользователь привязан ровно к Document Root домена;
- секреты: `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`;
- сервер из текущих заметок — `185.181.230.90`, но перед production проверь с владельцем, что для `vw-club.md` используется тот же аккаунт и IP;
- предполагаемый пользователь `deploy@vw-club.md` и Document Root `/home/chisinau/vw-club.md` нельзя считать созданными, пока владелец это не подтвердит.

Workflow не должен удалять чужие каталоги выше Document Root и не должен содержать пароль в YAML.

- workflow деплоя безопасно подготовлен;
- все перечисленные документы существуют и соответствуют фактическому коду;
- неизвестные внешние данные явно собраны в `TODO.md`;
- `PROJECT_MAP.md` и `DECISIONS.md` актуальны на момент сдачи.

## 15. Формат итогового отчёта владельцу

Отчёт должен быть кратким и понятным:

1. что готово;
2. какие проверки прошли;
3. что осталось в `TODO.md`;
4. какие данные или действия нужны от владельца;
5. готов ли проект к локальному просмотру, commit/push и production deploy — это три разных статуса.

Не перегружай владельца логом команд. Дай точные пути к главным документам и понятные следующие действия.

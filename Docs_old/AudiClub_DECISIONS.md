# DECISIONS — audi-club.md (ADR)

## ADR-001. Статический вывод, FTP-деплой на cPanel
Пайплайн клонирует bravo-motors: Astro (пиновано **6.4.6**, exact), `output: 'static'`, деплой содержимого сборки по FTP через GitHub Actions. Отличие от bravo-motors: прод-папка здесь `./dist/` (не `./dist/client/`), потому что Node-адаптер в прод-сборку не входит (см. ADR-004).

## ADR-002. trailingSlash: 'always'
Прямой урок bravo-motors: 71 внутренний 301 из-за отсутствия завершающих слэшей на Apache. Все внутренние ссылки строятся хелпером `l()` из `lib/i18n.ts`, который гарантирует слэш.

## ADR-003. i18n: RU в корне, RO под /ro/; отдельные коллекции per-locale
`articles_ru` / `articles_ro` — раздельные коллекции (решение брифа: проще редактировать, ничего не перепутать). Связь версий — по совпадению имени файла; hreflang выводится только при реально существующем переводе, x-default → RU. Сокращённый RO-перевод допустим.

## ADR-004. Keystatic — только локально
`npm run cms` (= `KEYSTATIC=true astro dev`) динамически подключает React, Keystatic и Node-адаптер. Обычный `npm run build` собирает чистую статику без серверного кода. Адрес редактора: `/keystatic/` — со слэшем (следствие ADR-002). Версии зафиксированы: @keystatic/core 0.5.x, @astrojs/node 10.x, @astrojs/react 5.x — мажоры выше требуют Astro 7.

## ADR-005. Модельные страницы из тегов
`/models/[model]/` генерируются из поля `model` frontmatter (lib/articles.ts → getModelGroups). Одна статья с несколькими моделями попадает на все соответствующие страницы. Slug: «Q5 8R» → `q5-8r`. Ключевая GEO/AEO-механика, заложена с первого дня.

## ADR-006. Schema.org
`Organization` клуба с полным sameAs (FB-группа, FB-страница, Instagram, Google Maps) — на каждой странице. `Article` на статьях, `CollectionPage` + `about: Car` на модельных страницах. На /partner/ — лёгкая ссылка на сущность `AutoRepair` BRAVO MOTORS без дублирования полного LocalBusiness (он живёт на bravo-motors.md — три сайта подтверждают одну сущность, а не плодят копии).

## ADR-007. Красный — только на интерактивном
Из брифа: акцент (переменная `--c-accent`, стартово #d81a1a из диапазона #E01414–#D40000) применяется только к кнопкам, активным пунктам меню, подчёркиваниям ссылок, рамке промокода. Декоративные элементы — монохром. Финальный оттенок подбирается правкой одной переменной в `tokens.css` на живых макетах.

## ADR-008. Фото Audi-колец в hero — осознанное отклонение от запрета символики
Бриф (п.1, п.6) запрещал символику Audi AG (кольца, слоган «Vorsprung durch Technik») ради защиты по товарным знакам. Тем не менее в hero используется фото решётки с кольцами из архива клуба — авторское фото владельца (не стоковое, не официальный маркетинг AUDI AG). Риск оценён владельцем как низкий: изображение автомобиля частного лица на некоммерческом клубном сайте не является товарным использованием знака. Решение принято владельцем осознанно и не пересматривается.

## ADR-009. Редакционный стандарт статей — структура и тональность (2026-07-12)
Утверждён формат «премиум-переработки» RU-статей (пилот: `bolyachki-audi-q5-8r.md`, `audi-a4-b8-a6-c7-2-0-tdi-slabye-mesta.md`). Ключевые правила: заголовок H2 — тема/агрегат, заголовок H3 — аспект (симптомы, причины, диагностика, решение); тональность — сдержанная, профессиональная, без разговорных формулировок. При переработке обновляются `title` и `description` в frontmatter; сохраняются поля `slug`, `date`, `model`, `engine`, `years`, `type`; старый заголовок фиксируется в HTML-комментарии `<!-- PREVIOUS TITLE: … -->` сразу после frontmatter.

## ADR-010. Запрет разговорной лексики в публичных текстах (2026-07-12)
`docs/EDITORIAL_GUIDELINES.md` запрещает в текстах, видимых посетителю: «болячки», «маслоед», «убитый», «умирает», «добить», «бежать» и аналоги. Утверждённые замены: «болячки» → «характерные неисправности» / «типичные проблемы» (по контексту), «маслоед» → «повышенный расход масла», «убитый/умирает/добить» → «изношенный/выходит из строя/повредить». Правило распространяется на `*.astro`, `*.ts` и контентные файлы. Исключения: HTML-комментарии (`<!-- … -->`); поле `type: 'болячки'` в `content.config.ts` и `keystatic.config.ts` — внутренний идентификатор типа статьи, посетителю не виден, замене не подлежит. UI-лейбл `typeLabel.болячки` в `i18n.ts` — публичный, изменён на «Типичные проблемы» (RU); RO-вариант «Probleme tipice» был корректен изначально.

## ADR-011. Партнёрская страница: ссылка на карту BRAVO MOTORS (2026-07-12)
Кнопка «Открыть на карте» / «Deschide pe hartă» на `/partner/` вела на Google Maps профиль клуба. Исправлена ссылка в `src/components/pages/PartnerPage.astro`: `https://maps.app.goo.gl/Qo5aT4xakiDR7ZDVA` → `https://maps.app.goo.gl/fXY5Gn7yD1G5iJCv7` (профиль сервиса BRAVO MOTORS). Одновременно обе кнопки («Сайт BRAVO MOTORS» и «Открыть на карте») получили `target="_blank"` — внешние ресурсы должны открываться в новой вкладке; `rel="noopener"` уже присутствовал. Тексты RU и RO хранятся в одном объекте `copy`, правка покрывает оба языка.

## ADR-014. Google Analytics 4 (GA4) — только в PROD (2026-07-12)

В `<head>` `BaseLayout.astro` добавлены два `<script is:inline>` тега GA4 (Measurement ID `G-2V52DJT9EJ`), обёрнутые в `{import.meta.env.PROD && ...}`. Константа `GA_ID` объявлена в frontmatter-блоке компонента.

- **Только в PROD:** `import.meta.env.PROD` — `true` только при `npm run build`; при `npm run dev` / `npm run cms` значение `false`, скрипты в HTML не попадают. Это предотвращает загрязнение статистики дев-сессиями и локальными тестами.
- **`is:inline` обязателен:** без атрибута Astro пытается обработать `<script>` как ES-модуль (бандлинг, хэширование). `gtag()` и `dataLayer` — это legacy-паттерн с глобальными переменными, который несовместим с модульной обработкой. `is:inline` передаёт скрипт в HTML как есть.
- **`define:vars={{ GA_ID }}`** на втором скрипте позволяет передать frontmatter-константу в inline-контекст без строковой интерполяции вручную.
- Весь существующий SEO/OG/hreflang/Schema.org в `<head>` не тронут.

## ADR-013. Breadcrumbs: JSON-LD BreadcrumbList + визуальная навигация (2026-07-12)

Реализованы хлебные крошки в трёх форматах одновременно: визуальный `<nav>` с `aria-label="Breadcrumb"`, JSON-LD `BreadcrumbList` (добавлен в единый массив `schemas` в `BaseLayout.astro`, рядом с `Organization`/`Article`/`CollectionPage` — ADR-006 не нарушен), автоматическое скрытие на главных страницах (`/` и `/ro/`).

**Ключевые архитектурные решения:**

- `path` проп `BaseLayout` — всегда без `/ro` префикса; `buildBreadcrumbs()` применяет `l(locale, path)` для генерации реальных href, поэтому один вызов покрывает оба языка.
- Для динамических страниц (`/models/[slug]/`, `/zhurnal/[slug]/`) добавлен необязательный проп `crumbLabel` — страница передаёт уже известное ей название (`group.model`, `article.data.title`), а не реконструирует его из slug. Fallback-десалаг (`q5-8r → Q5 8r`) присутствует, но считается временным состоянием.
- Статичные страницы (`/partner/`, `/models/`, `/zhurnal/`, `/o-klube/`) не трогались — их метки вынесены в словарь `crumbLabels` в `lib/i18n.ts`.
- Модельные страницы имеют 3 уровня (Главная → Модели → Q5 8R); журнальные — 2 уровня (Главная → Заголовок статьи), т.к. архивная страница журнала не является обязательным пунктом пути.
- Стили используют переменные `--c-text-soft` / `--c-text` / `--c-line` / `--font-sans` из `tokens.css` (в bravo-motors были другие имена — `--muted`, `--ink`, `--font-mono`).

## ADR-012. Git: единственная ветка main (2026-07-12)
До этой сессии рабочей веткой по умолчанию была `master`, тогда как `origin/HEAD` указывал на `origin/main`. Коммиты случайно попадали в `master`. Решение: ветка `master` (локальная и remote) удалена, все изменения переведены в `main`. В конфиге репо задан `init.defaultBranch = main`, апстрим `main → origin/main` подтверждён. Единственная ветка проекта — `main`.

## ADR-015. Публикация ориентиров стоимости в статьях (2026-07-14)

Ценовые TODO в статьях 1–2 закрыты данными технического партнёра BRAVO MOTORS. Все суммы:

- публикуются как ориентиры в молдавских леях, а не как фиксированная оферта;
- содержат пояснение, что входит в сумму: работа, детали, расходные материалы или диагностика;
- датируются июлем 2026 года и требуют последующей периодической проверки;
- дублируются без смысловых расхождений в RU- и RO-версиях;
- не заменяют диагностику, подбор по VIN и дефектовку.

Редакционная цель — помочь владельцу оценить порядок затрат, не обещая одинаковую стоимость или результат для всех автомобилей.

## ADR-016. Временные изображения статей: WebP, медиакарта и атрибуция (2026-07-16)

До появления собственного фотоархива клуба статьи используют временные интернет-изображения с обязательным префиксом `web-`. Префикс позволяет найти и пакетно заменить такие файлы фотографиями клуба или сервиса без аудита всего `public/`.

Приняты следующие правила:

- фотографии хранятся локально в `public/images/articles/`, а не загружаются со сторонних серверов при открытии страницы;
- растровые фотографии публикуются в WebP: SVG не применяется, поскольку не уменьшает вес растрового изображения;
- исходники Audi MediaCenter используются только при наличии отметки о бесплатном редакционном использовании;
- для Commons сохраняются автор и лицензия, атрибуция выводится непосредственно возле изображения;
- передний и задний ракурс должны относиться к одному экземпляру автомобиля; это проверяется визуально, а не только по имени файла;
- для статьи о нескольких моделях используется отдельная согласованная пара каждой модели;
- техническое изображение сверяется по семейству и объёму двигателя либо прямо маркируется как схема связанной системы;
- RU и RO используют одни файлы, но получают собственные `alt` и подписи.

Медиа не включены во frontmatter, чтобы не дублировать одинаковые пути, лицензии и атрибуцию в двух локалях. Единым источником является `src/lib/articleMedia.ts`, ключ — совпадающий RU/RO slug статьи. `ArticleCard.astro` берёт первый элемент как обложку, а `ArticlePage.astro` формирует обложку, галерею и Schema.org/OG image. Полный реестр источников хранится в `Docs/IMAGE_SOURCES.md`; воспроизводимая загрузка и оптимизация — в `scripts/fetch-web-article-images.mjs`.

## ADR-017. Связанный Schema.org graph и автоматический SEO-контроль (2026-07-16)

По результатам SEO/GEO/AI Search аудита разрозненные JSON-LD блоки заменены единым `@graph` в `BaseLayout.astro`. На каждой странице граф связывает стабильными `@id` сущности `Organization`, `WebSite`, `WebPage`, `ImageObject`, `BreadcrumbList` и, при наличии, страницу конкретного типа (`Article`, `CollectionPage`, `AutoRepair`). Это уточняет и дополняет ADR-006 и ADR-013.

Принятые правила:

- базовые идентификаторы: `/#organization`, `/#website`, `/#logo`; сущности страницы используют canonical URL с фрагментами `#webpage`, `#article`, `#primaryimage`, `#breadcrumb`;
- клуб остаётся независимой `Organization`, не подразделением AUDI AG; `areaServed` ограничен Молдовой;
- автором статей указывается редакция `Audi Club Moldova` как подтверждённая организация; `Person`, reviewer, стаж и статистика не создаются без реальных данных;
- `Review`, `AggregateRating`, `FAQPage` и `SearchAction` не добавляются без соответствующего видимого контента и работающей функции поиска;
- логотип Schema ссылается на существующий `/logo-dark.svg`, а не на отсутствующий `/logo.svg`;
- 404 получает `noindex, follow`; остальные публичные страницы — расширенную robots-директиву с разрешением больших превью;
- Open Graph и Twitter Card формируются централизованно; статьи передают дату публикации и alt главного изображения;
- статьи включают существующий индекс журнала в визуальные и JSON-LD breadcrumbs;
- у контентных изображений фиксируются размеры; главное изображение получает высокий приоритет, галерея остаётся lazy-loaded.

После production build запускается `npm run audit:seo`. Скрипт без сторонних зависимостей проверяет 49 HTML-страниц: title, description, canonical, H1, lang, Open Graph, Twitter image, JSON-LD, alt, дубли metadata, внутренние ссылки и согласованность с sitemap. Длина title/description является предупреждением, а не причиной провала: массовое механическое сокращение не выполняется без редакционного решения и SERP-данных.

Подробный отчёт и ручные задачи владельца зафиксированы в `Docs/SEO-GEO-AI-AUDIT.md`.

## ADR-018. Второй проход Schema.org: централизованный генератор и проверка production HTML (2026-07-16)

Повторный аудит после отчёта Screaming Frog `Structured Data: Total Types = 0` подтвердил, что актуальная локальная production-сборка уже выводила JSON-LD непосредственно в HTML. Поэтому расхождение с crawl считается внешним до повторной проверки после deploy: опубликованный сервер мог отдавать предыдущую сборку, кэшированную версию или содержимое другой директории.

Чтобы сделать результат воспроизводимым и исключить неоднозначность реализации, принято:

- хранить построение базового `@graph` и стабильные идентификаторы в `src/lib/seo/schema.ts`;
- выводить граф единым статическим компонентом `src/components/seo/JsonLd.astro` без hydration и клиентских запросов;
- сериализовать JSON-LD с заменой `<`, `>`, `&`, U+2028 и U+2029 escape-последовательностями, исключая преждевременное закрытие `<script>`;
- связывать `WebPage`/`CollectionPage`, `ImageObject` и `BreadcrumbList` через canonical-based `@id`;
- использовать `CollectionPage` для индексов журнала, моделей и страниц конкретных моделей;
- не выводить JSON-LD на noindex-странице 404 и не включать её в sitemap;
- не публиковать неподтверждённые `foundingDate`, адрес партнёра, Person, Review, AggregateRating, FAQPage или SearchAction;
- проверять собранный `dist`, а не исходные компоненты, двумя командами: `npm run audit:seo` и `npm run audit:schema`.

`audit:schema` обязан завершаться ошибкой при отсутствии JSON-LD на индексируемой странице, невалидном JSON, пустом `@graph`, отсутствии Organization/WebSite/типа страницы, отсутствии Article у статьи, отсутствии BreadcrumbList на вложенной странице или дублировании `@id`. Текущий эталон: 49 HTML-файлов, 48 индексируемых страниц с JSON-LD, одна noindex 404 без JSON-LD, 0 ошибок парсинга.

## ADR-019. Адаптивные изображения обязаны сохранять пропорции (2026-07-16)

После публикации изображений статей обнаружено вертикальное растяжение на узких экранах. Причина находилась в глобальном reset: `max-width: 100%` ограничивал ширину `<img>`, но HTML-атрибут `height` продолжал задавать фиксированную высоту. При уменьшении ширины браузер получал непропорциональный прямоугольник.

Принято глобальное правило `img, video { height: auto; }` в `src/styles/global.css`. Оно дополняет существующий `max-width: 100%` и заставляет растровые изображения и видео пересчитывать высоту пропорционально фактической ширине. Локальные компоненты с осознанным кадрированием (`object-fit: cover` и явно заданной CSS-высотой) сохраняют свои более специфичные правила.

Файлы изображений не перекодировались: проверка метаданных подтвердила корректные пропорции исходных и мобильных WebP. Исправление относится только к адаптивному CSS-поведению.
